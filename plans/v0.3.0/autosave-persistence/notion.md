# Notion — autosave-persistence

## Status

`done`

## Context

Milestone v0.3.0 (player-facing layer), spec
[`cosmic-navigation-engine-v0.4.md`](../../../docs/techstack/cosmic-navigation-engine-v0.4.md)
§10 (Persistence — resolved for v0.4 scope). Decided by ADR-004 in
[`../../docs/decisions/`](../../../docs/decisions/). Procedural regions are
never saved (ADR-019 determinism); the payload is ship + navigation +
metadata.

## Problem & Needs

- Sessions must resume deterministically mid-flight, mid-transition,
  mid-handoff without storing regenerable content.

## Goals

1. **Binary autosave** persisting: ship state (active-frame ID, 6D
   position/velocity in-frame, orientation quaternion, mass, fuel,
   active control state); navigation state (select-to-focus target,
   active transition plan, time-compression mode/multiplier); metadata
   (format version, master seed, real-world + simulation timestamps,
   session playtime, catalog version IDs, integrity checksum).
2. **Triggers:** confirmed frame transitions, completed SOI handoffs,
   fly-to start/completion, explicit suspend/quit, user-configurable
   periodic interval.
3. **Atomic writes:** temp file + rename; ≥ 2 rotating recovery
   snapshots.

## Non-goals

- Procedural region caching (regenerated by ADR-019 determinism).
- Migration tooling beyond version reject + checksum verify (format v1
  has no predecessors).

## Users / Stakeholders

- Players: never lose a session.
- Developers: deterministic resume for debugging long journeys.

## Roles

Author: PO (2026-09-17). UX consulted (2026-09-17): approved save-indicator
and interval behavior (notes below). ARCHITECT consulted (2026-09-17):
approved `engine::save` (envelope codec + atomic writer + rotation, thin fs
layer per `catalog::io` precedent) + `game::save` (trigger policy); invariants
— procedural content never saved (ADR-019) and the corrupt-save contract
(backup + clean error, never boot-loop).

## Functional requirements

- Binary writer/reader with format-version + integrity checksum.
- All ADR-004 triggers wired to engine events.
- Atomic rename + snapshot rotation; corruption falls back to the
  previous snapshot.

## Non-functional requirements

- Save round-trip test: resume bit-identical simulation state
  (deterministic resume, spec §10).
- Quality gates in `docs/techstack/quality.md` stay green;
  `persistence.md` updated.

## Definition of Done

- [x] Round-trip tests: resume mid-flight, mid-fly-to, post-handoff —
  state identical.
- [x] Corruption test: truncated save rejected via checksum, recovery
  snapshot loads.
- [x] Every ADR-004 trigger demonstrably fires (event log evidence).

## Constraints & Assumptions

- ADR-004 draft becomes binding here.
- Save format documents catalog version IDs (ADR-020) so epoch-mismatched
  saves are detectable.
- Integrity checksum is FNV-1a 64 (hand-rolled, zero new deps) — corruption
  and truncation integrity, not an adversarial MAC. Decode order per ADR-004:
  magic/length → checksum → version → parse.
- The real-world timestamp is metadata only; it is excluded from resume
  determinism (sim state derives from seed + sim fields alone).
- UX notes (2026-09-17): periodic interval default **120 s**, clamped range
  **30–600 s**, fed by the caller (no wall-clock in logic). A successful
  autosave shows a transient single-line notice; a failure shows a distinct
  persistent warning and never crashes or boot-loops. The quit trigger fires
  on clean exit. The settings UI binds when the windowed shell lands — the
  interval is a config field until then.
- Non-goals recorded: JSON sidecar / `tools` converter, 3 manual save slots
  (M1-era `persistence.md` aspiration superseded by the ADR-004 autosave
  ring; the doc is updated accordingly), network/cloud saves.

## Resolved design notes

- Configurable interval: default 120 s, clamped to 30–600 s (UX decision
  2026-09-17, recorded under Constraints & Assumptions).
