# Rust Documentation Review Checklist

- [ ] The page states whether guidance is baseline, target, planned, or open.
- [ ] Claims match stable Rust or link to the source that qualifies them.
- [ ] Code examples compile, or the page explains why they are illustrative.
- [ ] Ownership, mutation, error, and thread-safety boundaries are explicit.
- [ ] Unsafe code documents invariants and tests the safe boundary.
- [ ] Pattern use has a concrete problem and an avoid case.
- [ ] Public API and dependency-direction effects are identified.
- [ ] Performance claims include a measurement plan or result.
- [ ] Links are authoritative, current, and listed in curated references.
- [ ] Migration changes preserve a buildable rollback point.
