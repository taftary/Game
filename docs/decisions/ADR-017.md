# ADR-017: Star catalog streaming — HEALPix tiling + deterministic fallback

- **Status:** binding (2026-09-17, `plans/v0.2.0/star-catalog-streaming`
  done: `engine::catalog` implements the index, tile format, cache,
  scheduler, fallback, and identity; cooker + debug sky surface ship
  alongside)

## Context

Gaia DR3 holds ~1.8 billion stars; real catalog data cannot be fully
memory-resident (spec §8). Streaming needs a stable all-sky spatial index.

## Decision

- **HEALPix spatial index**, order 12–14 chosen per catalog-density tier
  and device memory class (order 12 = default: nside 4096, 2.0×10⁸
  pixels, 51.5″ resolution; order 13 for dense galactic plane; order 14
  premium close-ups).
- **Budgets:** 2 GB active star-tile memory (decoded attributes +
  GPU-ready buffers); < 100 ms asynchronous tile-load latency once data
  is local; priority order view-frustum → predicted travel direction →
  camera distance.
- **Fallback:** if a tile is unavailable after 200 ms, render a
  deterministic procedural stand-in from tile metadata (approximate
  source count + mean color, seeded golden-angle lattice), replaced
  seamlessly on arrival. Catalog and fallback share **stable object/tile
  identifiers** so replacement never affects selection, focus targeting,
  or navigation state.

## Consequences

- Golden-angle lattice reuses the math toolkit (spec §7) already adopted
  for crater/star placement.
- Offline-first vs network streaming policy is an open product item
  (spec §10); this ADR covers the in-memory/index side only.
- Concurrency is `std::thread` workers + `mpsc` (spec §10 PO decision
  2026-09-17): no async runtime, no new dependency — `stack.md`
  untouched. Decode is pure; worker timing affects arrival order only,
  never tile content or simulation state.
