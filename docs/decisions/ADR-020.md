# ADR-020: Real-data policy — ephemeris, Gaia validity, Earth geodesy

- **Status:** draft (2026-09-17, proposed by navigation-engine spec
  [`cosmic-navigation-engine-v0.4.md`](../techstack/cosmic-navigation-engine-v0.4.md)
  §5/§8; binding when `plans/v0.1.0/scale-physics` and
  `plans/v0.2.0/star-catalog-streaming` land)

## Context

The spec's anchor promise is "real astronomical data wherever it exists"
(§8). Each dataset needs a validity window and a fallback behavior so the
simulation never silently extrapolates nonsense.

## Decision

- **Planetary positions:** VSOP87 default (3000 BCE – 3000 CE); optional
  DE440-derived simplified elements for outer planets (Jupiter–Neptune)
  in high-precision mode (10000 BCE – 10000 CE).
- **Stars:** Gaia DR3 positions + proper motions, streamed (ADR-017).
  Linear proper-motion extrapolation valid **±1000 years** from Gaia DR3
  epoch 2016.0; beyond that, display a warning and optionally switch to
  procedural jitter.
- **Earth geodesy:** WGS84 for ECEF; real latitude/longitude for the
  facility anchor; real terrain data at regional/aerial scales (dataset
  + licensing is an open product item, spec §10).
- **Cosmic web / supercluster:** no consumer-scale renderable catalog
  exists — use seeded, cosmologically plausible procedural structure and
  **explicitly flag it as procedural**, never as real data.

## Consequences

- Catalog version identifiers are save metadata (ADR-004) so saves
  record which real-data epoch they were built against.
- Simulation timestamps outside validity windows must surface in the
  HUD/debug UI, not fail silently.
