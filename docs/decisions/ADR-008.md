# ADR-008: ECS — adopt `hecs`

- **Status:** accepted (2026-09-14, plans/build-foundations)

## Context

`engine::sim` needs colonies, robots, resources, and a tick loop
(M4). `docs/techstack/stack.md` listed "ECS/scheduling" as owned cost
with no decision. Options: custom ECS (maximum control, highest
cost — the classic way custom-engine projects die before the game
exists), `bevy_ecs` (full-featured, heavier tree + compile cost),
`hecs` (minimal, deterministic-friendly).

## Decision

- Adopt **`hecs`** (workspace dep, wired into `game_engine`) for
  entity/component storage in `engine::sim`.
- **Scheduling stays custom**: a thin fixed-step scheduler we own
  (20 Hz tick per [`../techstack/simulation.md`](../techstack/simulation.md));
  no `bevy_app`/`bevy_ecs` schedule import.
- Determinism rules still hold: sim state hashable, fixed-step
  regression via recorded inputs; `hecs` internals never leak into
  save format (serialize plain data, not archetypes).

## Consequences

- M4 builds gameplay on `hecs` instead of inventing storage.
- If `hecs` fails determinism or mobile-perf needs, replace behind
  the `engine::sim` boundary — gameplay code must not name `hecs`
  types in public APIs beyond the sim module.
