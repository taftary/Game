# ADR-010: Cell-chunk identity (chunk = dual cell)

- **Status:** accepted (2026-09-15, plans/cell-chunks)

## Context

M2 needs chunk identities to stream against ("chunk streaming stub",
`docs/milestones/README.md`), and `docs/game/universe.md` already
promises lazy surface generation "per chunk" — but no plan defined what
a chunk *is*. The `engine::hexsphere` dual mesh (ADR-002) already owns
a stable, committed-hash-pinned cell index space (10·4^N+2 cells:
hexagons + exactly 12 pentagons); the Sphere Viewer needed a visual
anchor for those indices (`plans/cell-chunks`).

## Decision

- **Chunk identity = cell index.** `engine::hexsphere::ChunkId` wraps
  the dual cell's `u32` index: 1 cell = 1 chunk, pentagons included
  (first-class, never special-cased). Stable per `(subdivisions,
  radius, GEOMETRY_VERSION)` — the key M2 streaming and per-chunk
  surface layers load against.
- **Grouping deferred to M2.** If streaming wants patches/regions
  (likely at N=6's 40,962 cells), they are built *from* these ids;
  chunk identity itself never re-numbers. `ChunkId` construction stays
  engine-private (`HexSphere::chunk_id`) until the first per-chunk data
  layer decides the serialization shape.

## Consequences

- Debugger hover/pin (`game_debug`) reports the same id streaming will
  use — no throwaway debug-only identity.
- Existing `u32` cell accessors stay; no migration ripple through
  `render`/`uv` internals.
- Terminology: *cell-chunk* (this ADR) vs *surface chunk* (M2 lazy
  terrain detail) — `universe.md` clarifies the line.
