# ADR-007: Reference devices, device floor, perf harness

- **Status:** draft (2026-09-14, plans/v0.0.1/build-foundations) — floor and
  harness decided now; reference devices finalized by M6.

## Decision (proposed floor)

- **Android floor:** API 26+ (Android 8.0), Vulkan 1.1. Devices below
  the floor get the explicit "unsupported" screen (see
  [`../risks/README.md`](../risks/README.md)); no silent GLES
  fallback without a new ADR.
- **iOS floor:** iOS 15+ via MoltenVK. If MoltenVK quality on the
  reference device fails the ADR-001 kill-switch, iOS drops to
  best-effort by ADR — v1 ship is not held hostage by it.
- The floor defines the Low tier in
  [`../techstack/quality.md`](../techstack/quality.md): M1+ Vulkan
  code may not require anything above Vulkan 1.1 core in the
  gameplay-critical path.

## Reference devices

Named by M6 (mobile hardening) at the latest; M1 smoke runs against
the Low-tier device *class* (mid-tier phone, ≤1080p dynamic). No
feature ships unless it runs on Low or is tier-gated.

## Perf harness

`crates/tools` renderer smoke + device profiles enforce the budgets
(synthetic seeded planet + bot colony; informational in v1, gates in
later milestones). Sustained 15-min thermal session must not throttle
below Low-tier fps.

## Apple / MoltenVK renderer + packaging requirements
(amended 2026-09-14)

- **M1 renderer must enumerate `vulkan-portability`** where required
  and handle `VK_KHR_portability_subset` on Apple targets. The
  Vulkan 1.1 floor above does not cover this — it is Apple-specific
  code, and the iOS compile-guard cannot catch a *missing*
  enumeration. (See [`../techstack/rendering.md`](../techstack/rendering.md).)
- **MoltenVK ships as the static XCFramework** (App-Store-safe;
  Apple rejects dynamic-dylib embedding at review). Minimum runtime
  iOS 15 matches the floor above.
- Packaging (`staticlib` + Xcode wrapper app vs. packager evaluation),
  signing/provisioning, and on-device runs stay M6. CI checks iOS
  compilation only — it can never produce a signed IPA without
  Apple Developer secrets.

## Consequences

- M1 renderer code is written against the Vulkan 1.1 floor from day
  one, even though on-device measurement lands in M6.
- CI guards mobile *compilation* from now; on-device numbers start M1
  (smoke) and gate from M6.
