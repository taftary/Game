# ADR-019: Procedural seeding — hierarchical seeds + domain separation

- **Status:** draft (2026-09-17, proposed by navigation-engine spec
  [`cosmic-navigation-engine-v0.4.md`](../techstack/cosmic-navigation-engine-v0.4.md)
  §6; binding when `plans/v0.1.0/hierarchical-seeding` lands)

## Context

The universe must regenerate identically without save data (spec §6
determinism), and one region must be regenerable/debuggable without
changing others. Naive seed reuse across content layers creates
correlated artifacts.

## Decision

- **Hierarchical seeds** from a single master seed:
  `region_seed = hash(master_seed, frame_id, cell_coordinates)`.
- **Domain separation:** never reuse a raw region seed across content
  layers; derive sub-seeds — `hash(region_seed, "galaxy_arms")`,
  `hash(region_seed, "star_field")`, `hash(region_seed, "crater_field")`.
- **Real-data override:** cataloged real objects (Gaia stars,
  JPL-tracked planets) are fixed overrides; procedural generation is
  suppressed inside an exclusion radius around them, checked **before**
  the procedural hash fires for the cell.
- **Determinism:** procedural content is a pure function of
  `(seed, position)`, never stored; same seed ⇒ identical regions across
  sessions.

## Consequences

- Master seed is save metadata (ADR-004) — changing it forks the
  universe.
- Exclusion-radius checks add a catalog lookup to the generation hot
  path; budget covered by `plans/v0.2.0/star-catalog-streaming` tiling.
