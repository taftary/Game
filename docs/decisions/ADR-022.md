# ADR-022: Unified debug shell — single window, parity rule

- **Status:** accepted (2026-09-17, PO + UX decision)

## Context

`game_debug` grew two OS windows (`plans/v0.0.1/debug-ui-reorganize`,
2026-09-16): a viewer window (Galaxy Map / System Map / Planet View)
and a tools window (FPS / Console / Inspector / Transitions / Scale /
Dimensions). The tools tabs duplicate each other and the viewer: the
Scale tab lists the ten waypoint dimensions plus a transition-event
log, the Dimensions tab re-lists L1–L5 views, the Transitions tab
repeats current transition + history, and map data renders in both
windows. Two windows split input focus and every binding is
hardcoded across `main.rs` with no single listing.

## Decision

- **One window.** The tools window is deleted; one `winit` window,
  one event loop, one nav model: `GAME DEMO` · `DIMENSIONS:
  <active layer>` (dropdown of the 10 waypoints) · `SETTINGS`.
  This reverses the `debug-ui-reorganize` two-window model; that
  plan stays literally true as a historical record (per ADR-011
  convention: numbers/labels are history, not sequence).
- **Key↔button parity.** Every debug action is a named `Action`
  with exactly one fixed key and one button label showing that key;
  the Settings → Controls section renders the whole registry
  (grouped, read-only for v0.3.1).
- **Chrome never shadows game keys.** Content keys (WASD/arrows, U,
  P, E, T, Q, F, R, G/B, Home, `1`–`6` shader modes, F5 twilight)
  are reserved; chrome lives on F1–F3, `` ` ``, F6–F8, F9–F10,
  dropdown-captured digits, and Esc (which unwinds UI focus and no
  longer quits; exit is the window close button).
- **Homeless panels fold, not tabs:** transitions become an
  in-flight bottom-center pill + console log feed; FPS/Console/Inspector become
  one overlay widget's sub-tabs; Scale becomes the dropdown itself.
- **Polish (2026-09-17 screenshot review):** the top bar is always
  visible (no BAR toggle — demo tab keeps the bar, hides docks +
  widget); dock toggles shift to F9 (left) / F10 (right); the three
  toggle buttons live inside the top bar right-aligned; the
  Dimensions dropdown is a solid-black bordered menu
  (360 px, padded rows) with drop shadow, hover lift, row separators
  and right-aligned status, drawn as the last chrome layer so it
  always sits on top; docks grow to 260/300 px with 12 px padding.

## Consequences

- `crates/debug` shell modules (`app`, `ui`, window code in
  `main.rs`) are rewritten; `game`/`engine` are untouched and
  consumed read-only (no simulation mutation from debug UI).
- Done debug plans (`debug-screens`, `debug-ui-reorganize`,
  `scale-debug-screens`, `dimension-debug`) stay literally true as
  history; their screens are superseded, not rewritten.
- `docs/game/controls.md`, `docs/techstack/architecture.md`,
  `docs/techstack/rendering.md` (debug-shell parts only —
  camera/screen-space invariants preserved), `docs/game/journey.md`,
  `docs/roles/ux.md` (debug-exemption gate gains a
  presentation-accurate exception), and `docs/roles/security.md`
  are updated with the v0.3.1 feature; techstack version bumps to
  `0.32.0`.
