# ADR-002: Planet representation — hex-dominant geodesic dual mesh

- **Status:** accepted (2026-09-14, plans/v0.0.1/hex-sphere)

## Context

Planets need one representation serving two masters: the gameplay data
grid (biomes, resources, colony placement per cell) and the renderer's
far-field mesh. Candidates were sphere quadtree, cube-sphere,
heightfield cap — plus the hex-dominant geodesic dual mesh (icosahedron
→ subdivide → relax → dual) implemented in `engine::hexsphere`
(plans/v0.0.1/hex-sphere). Constraints: mobile memory, O(n) cell passes,
deterministic output, no heavy physics.

## Decision

- Adopt the **hex-dominant geodesic dual mesh** as the single sphere
  representation for every spherical body (planets first; stars, moons
  later). Canonical implementation: `engine::hexsphere::HexSphere`
  (N parameter, default 6 → 40,962 cells, exactly 12 pentagons).
- **Rejected:** sphere quadtree (pole pinching, non-uniform cells,
  forces separate sim/render topologies); cube-sphere (seam handling,
  non-uniform cells); heightfield cap (not a global representation).
- The 12 pentagons are first-class cells (Euler forces them), never
  special-cased hacks in gameplay or rendering.
- Geometry is seed-independent: one mesh per (N, radius) shared across
  bodies; per-seed variety stacks in later world-gen layers.

## Consequences

- `docs/techstack/rendering.md` far-field line now names the
  `HexSphere` dual mesh; per-tier subdivision level (or decimation) is
  chosen when M1 consumes it — LOD strategy deferred, not decided here.
- `engine::hexsphere` stays pure + deterministic with a committed mesh
  hash; any geometry change bumps `GEOMETRY_VERSION`, never silent drift.
- M2 descent streaming and surface layers build on cell ids from this
  mesh; save format references cells by stable index (migration rule per
  universe versioning).
