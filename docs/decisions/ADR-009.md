# ADR-009: Allocator + logging defaults

- **Status:** accepted-default, validate in M1 (2026-09-14,
  plans/v0.0.1/build-foundations)

## Context

Cold-start (<5 s), memory (<1 GB Low tier), and in-app diagnostics
(`game_debug` console) all need decisions the scaffold didn't make:
global allocator and log/trace backend.

## Decision

- **Allocator default: `mimalloc`.** Rationale: lower fragmentation
  and better multithreaded behavior than the system allocator on both
  mobile OSes; small, well-understood integration. Validated in M1
  against the Low-tier memory budget — if it regresses cold start or
  peak RSS vs. system allocator, revert by ADR.
- **Logging/tracing: `tracing` + `tracing-subscriber`.**
  `game_engine` emits `tracing` events/spans (already wired as a
  dependency); binaries install the subscriber. Dev/desktop: `fmt`
  layer. Android (M6): logcat layer. The `game_debug` log console
  consumes a `tracing` layer — no second log facade.

## Consequences

- M1 wires `mimalloc` as global allocator behind a feature flag so
  the A/B comparison is one flag flip.
- No `log`-crate facade: `tracing` only, to avoid two event systems.
- Audio (`rodio`, ADR-006) inherits the same allocator; no per-crate
  allocator decisions.
