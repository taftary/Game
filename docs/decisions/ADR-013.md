# ADR-013: GPU precision — floating-origin rendering

- **Status:** draft (2026-09-17, proposed by navigation-engine spec
  [`cosmic-navigation-engine-v0.4.md`](../techstack/cosmic-navigation-engine-v0.4.md)
  §3; binding when `plans/v0.1.0/frame-hierarchy` lands)

## Context

Vulkan pipelines consume `f32` vertex data; `f32` has ~7 decimal digits,
useless beyond ~10 km from origin at meter resolution. The frame tree
(ADR-012) keeps CPU-side truth in `f64` or non-dimensionalized units, but
the GPU still needs camera-local coordinates every frame.

## Decision

- **Floating-origin rendering:** every frame, recenter world space on the
  camera and upload only camera-relative `f32` positions to Vulkano.
- The CPU-side frame tree carries `f64` (or per-frame non-dimensionalized
  units) for hierarchy portions far from the camera.

## Consequences

- Matches the existing "rendering stays f32 camera-relative" rule
  (ADR-011 consequences) — this ADR generalizes it to the full frame
  chain.
- Projection conventions in
  [`../techstack/rendering.md`](../techstack/rendering.md) (RH,
  Z ∈ [0, 1], no Y-flip) are unchanged; only the origin moves.
