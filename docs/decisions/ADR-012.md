# ADR-012: Coordinate architecture — hierarchical nested reference frames

- **Status:** binding (2026-09-17, `plans/v0.1.0/frame-hierarchy` done:
  `engine::frames` implements the chain; cosmic-limit amendment recorded
  in the spec §10 addendum *Resolved for v0.1.0*)

## Context

Spanning 10^26 m → 10^0 m (26 decades, spec §1) in one world space
exhausts `f64` precision at the small end even with periodic rebasing.
Celestia / SpaceEngine / KSP solve this with nested frames.

## Decision

- Adopt **hierarchical nested reference frames**, not a single rebasing
  `f64` world space. Frame chain (spec §3):

  ```text
  Comoving Cosmological (Mpc) └ Galactocentric (kpc) └ Local-Group (Mpc)
    └ Stellar-Neighborhood (pc/ly) └ Solar-System Barycentric (AU)
      └ Planetocentric (km, ECEF) └ Local Tangent-Plane ENU (m)
  ```

- Camera and ship true position = **composed transform chain**, resolved
  only through the active frame and its immediate parent; never flattened
  into one global coordinate.
- Each active frame uses a well-conditioned local unit system (spec §5
  non-dimensionalization): e.g. AU/day/solar masses in the solar-system
  frame with G normalized ≈ 1; km/s/planet masses in planetary frames.

## Consequences

- The player world frame stays true ENU (`east × north == up`) — extends
  the existing rendering invariants in
  [`../techstack/rendering.md`](../techstack/rendering.md) upward through
  the frame chain.
- Frame transitions are explicit state changes (see ADR-014 for SOI
  handoff, ADR-015 for time compression); no silent coordinate swaps.
- `plans/v0.0.1/scale-hierarchy`'s 8 journey levels map onto the 10 spec
  waypoints; `plans/v0.3.0/scale-debug-screens` visualizes the mapping.
