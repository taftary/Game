# ADR-027: Cosmic performance — measure first, then tier by device

- **Status:** accepted (2026-09-23, PO + ARCHITECT decision)
- **Extends:** ADR-026 (procedural GPU tracers, tier draw counts 1/2/8,
  veil Sprites/32/48, 5-level bloom), ADR-025 (field render, write-once
  bloom rule, tiering rule), ADR-007 (reference devices per tier, draft)
- **Amends:** nothing hashed, saved, or pipelined. Narrows one
  ADR-026 precedent: the debug shell's "windowed and capture both run
  the full High density" rule (`splat_k_default`, `veil_mode`,
  `MipBloomParams::for_tier(High)`) becomes tier-selected with an
  explicit `--tier` pin for captures.

## Context

The debug viewer runs hot on Demo + Inspector on Intel UHD 620,
`cargo run -p game_debug` (dev profile). Investigation (2026-09-23)
disproved the "multiple visible views" hypothesis — exactly one
`ViewContent` draws per frame (`draw_main`, `views` len 1) — and found
four root causes:

1. **The shell hard-codes High on every GPU.** `splat_k_default() → 8`
   (`main.rs:5856`), `veil_mode() → March{48}` (`main.rs:6126`),
   `BLOOM_LEVELS = 5` + `MipBloomParams::for_tier(High)` (`main.rs:1114`,
   `10092`). `quality.md` already budgets Medium/Low for this hardware
   class; the shell never reads `device_score` (`engine/render/boot.rs`).
   The tracer plan admits frame cost was never isolated
   (`plans/v0.3.4/cosmic-gpu-tracers/plan.md` step 5).
2. **The procedural splat draw dominates.** 8.58M vertex invocations /
   frame (`cells × k`, `main.rs:7572`), two 3D fetches each, zero
   frustum/fog/slab culling, 8× same-pixel overdraw at distance.
   Post (bloom ≈ 20M taps, march ≈ 2.8M fetches @720p) is an order of
   magnitude below.
3. **No GPU timing exists.** No `QueryPool`/timestamps anywhere;
   `FpsOverlay` records wall-clock loop interval only. Every grading
   round tuned blind.
4. **Dev-profile CPU tax.** `default-members` excludes `crates/debug`;
   `[profile.dev.package."*"]` covers external deps only, so
   `game_debug` + `game_engine` build at opt-level 0 — including the
   per-frame UI relayout, text shaping, 2× `Buffer::from_iter`, splat
   UBO + descriptor set.

## Decision

1. **Measure first (feature `cosmic-frame-timing`).** Timestamp query
   pool around scene+splats / bloom / march / main pass + CPU phase
   timers, shown in the FPS widget and logged by `--capture`. Zero
   readback cost when the widget is hidden. Rule going forward: **no
   cosmic grade/perf change ships without a per-pass GPU ms line**.
2. **Tier by device (feature `cosmic-device-tier`).** Boot mapping:
   `Cpu | VirtualGpu → Low`, `IntegratedGpu → Medium`,
   `DiscreteGpu → High`, `Other → Medium`. `GAME_DEBUG_TIER`
   overrides the mapping; `GAME_DEBUG_COSMIC_K` /
   `GAME_DEBUG_COSMIC_VEIL` keep overriding their knob (strict parse
   rules untouched). Captures take an explicit `--tier` (default High)
   so DoD shots stay byte-identical with v0.3.3/v0.3.4 evidence.
   Runtime tier cycling reuses the swapchain-recreate HDR rebuild path;
   write-once bloom holds at every level count
   (`assert_write_once` already covers `describe_bloom_chain(levels)`).
3. **Recorded follow-ups, gated on measured numbers** (not scheduled):
   `cosmic-splat-culling` (pre-fetch frustum reject + sub-sample LOD,
   shader-only), `cosmic-splat-bricks` (16³ bricks + indirect draws),
   `cosmic-fill-levers` (px clamps, per-frame resource ring, walker
   gate), post-chain trims only if bloom+march > 4 ms at Medium.
4. **Build hygiene with the timing feature:** `game_debug` +
   `game_engine` build at opt-level 1 under `cargo run`; budgets are
   measured with `--release` (recorded in `quality.md`).

## Consequences

- UHD 620 class hardware runs Medium by default (≈ 3–4× fewer splat
  invocations, one less bloom level, 32-step march) — to an
  already-specified tier, not a new look.
- `--capture` without `--tier` stays High: existing gates and shot
  hashes unaffected.
- The timing pool adds one `QueryPool` + a handful of timestamp writes
  per frame (µs); results are read one frame late, never waited on.
