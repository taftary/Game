# ADR-001: Stack lock + `vulkano` kill-switch

- **Status:** accepted (2026-09-14, plans/v0.0.1/build-foundations)
- **Context:** [`../techstack/stack.md`](../techstack/stack.md) locks
  `vulkano 0.35` / `winit 0.30` / `naga 30` / `fontdue 0.9` /
  `glam 0.33` for v1. `vulkano` on mobile (Android drivers, iOS via
  MoltenVK) is the least battle-tested part of that lock.

## Decision

- Stack versions stay locked for v1; an ADR overturns them.
- `winit` stays on the `raw-window-handle 0.6` line compatible with
  `vulkano 0.35` until `vulkano` catches up.

## Kill-switch (measurable `vulkano` fallback trigger)

If **either** fires, open a re-evaluation ADR (`wgpu` is the default
fallback candidate) instead of pushing through:

1. M1 renderer smoke fails to sustain **30 fps on the Low-tier
   reference device at 0.6x dynamic scale** after tier-gating is
   applied (see ADR-007), or
2. Surface creation fails on the **reference iOS device via MoltenVK**,
   or requires desktop-only Vulkan extensions in gameplay-critical
   code (violates [`../techstack/rendering.md`](../techstack/rendering.md)).

Rationale: without a trigger, "locked for v1" becomes a sunk-cost
trap on the riskiest technical leg. The trigger is cheap to write now
and expensive to invent under schedule pressure later.

## Consequences

- M1 must run the renderer smoke on at least the Low-tier reference
  device class before M2 builds on the renderer.
- `wgpu` stays unevaluated until a trigger fires — no spike work now.
